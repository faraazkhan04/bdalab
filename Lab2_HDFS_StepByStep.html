HDFS File Operations, Step by Step

Build the Hadoop image locally, bring up a real single-node HDFS (a NameNode + a DataNode), then write, seek-read, and list files on it from Java using the Hadoop FileSystem API.

PowerShell (host)Runs on your Windows machine — Docker commands.
Inside containerPrompt looks like hadoop@namenode:~$ — Hadoop & Java.

Download and prepare the image

Do this first on a fresh lab computer. This HTML contains the complete Dockerfile, Compose, XML, and Java code. Use the download buttons to create the files in any new folder.

3Dockerfile reference

The Dockerfile combines the official Hadoop image with a downloadable Java 8 compiler image. No Lab 1 files are required.

Dockerfile 
FROM eclipse-temurin:8-jdk AS jdk

FROM apache/hadoop:3.3.6

USER root
COPY --from=jdk /opt/java/openjdk /opt/java/openjdk

ENV JAVA_HOME=/opt/java/openjdk
ENV PATH=$JAVA_HOME/bin:$PATH
PHASE 1

Create the lab files

4Use docker-compose.yml

This defines two containers from the image you built: one NameNode (tracks where files live) and one DataNode (stores the blocks). The first start formats the NameNode automatically; named volumes keep HDFS data across restarts.

Use the Download docker-compose.yml button under the filename below and save the file in your new folder.

docker-compose.yml 
services:
  namenode:
    image: bda-hadoop-java:3.3.6
    hostname: namenode
    command: ["bash", "-lc", "if [ ! -f /data/name/current/VERSION ]; then hdfs namenode -format -force; fi; exec hdfs namenode"]
    ports:
      - "9870:9870"
    volumes:
      - namenode_data:/data/name
      - ./core-site.xml:/opt/hadoop/etc/hadoop/core-site.xml:ro
      - ./hdfs-site.xml:/opt/hadoop/etc/hadoop/hdfs-site.xml:ro
  datanode:
    image: bda-hadoop-java:3.3.6
    hostname: datanode
    command: ["hdfs", "datanode"]
    depends_on:
      - namenode
    volumes:
      - datanode_data:/data/data
      - ./core-site.xml:/opt/hadoop/etc/hadoop/core-site.xml:ro
      - ./hdfs-site.xml:/opt/hadoop/etc/hadoop/hdfs-site.xml:ro

volumes:
  namenode_data:
  datanode_data:
⚠
Why the old file failed Compose env_file only creates environment variables; Hadoop does not turn those variables into XML configuration. The XML files below are mounted directly where Hadoop reads them.

PHASE 2

Start HDFS

7Clean old HDFS containers before starting

A previous NameNode can own port 9870. Stop only containers publishing that port. If this lab was already started and the NameNode still fails, remove this Compose project's old containers and volumes so it can format a clean NameNode.

PowerShellhost · current lab folder
docker ps --format "table {{.ID}}\t{{.Names}}\t{{.Image}}\t{{.Ports}}"
docker ps --filter "publish=9870"
$old = docker ps -q --filter "publish=9870"
if ($old) { docker stop $old }
docker ps --filter "publish=9870"
✓
Checkpoint The final port listing should be empty before continuing.
PowerShellonly if this lab previously failed

⚠
Reset warning down -v deletes this lab's HDFS data and forces a fresh NameNode format. Use it only before a retry or when you no longer need the old lab data.
8Launch and verify the cluster

-d runs it in the background. The NameNode formats itself only when its volume is empty, then both daemons start.

PHASE 3

Copy the program into the container

10Download HdfsDemo.java, then copy it in

Use the Download HdfsDemo.java button under the filename below and save the file in your new folder, then copy it into the running NameNode from a second PowerShell window.

PowerShellhost
docker compose cp HdfsDemo.java namenode:/opt/hadoop/HdfsDemo.java
HdfsDemo.java 
import java.net.URI;
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.FileStatus;
import org.apache.hadoop.fs.FileSystem;
import org.apache.hadoop.fs.FSDataInputStream;
import org.apache.hadoop.fs.FSDataOutputStream;
import org.apache.hadoop.fs.Path;

public class HdfsDemo {
    public static void main(String[] args) throws Exception {
        String uri = "hdfs://namenode:8020";
        Configuration conf = new Configuration();
        FileSystem fs = FileSystem.get(URI.create(uri), conf);
        Path file = new Path("/user/student/quangle.txt");

        // WRITE: create() gives an output stream (sequential only)
        FSDataOutputStream out = fs.create(file);
        out.writeBytes("On the top of the Crumpetty Tree\n");
        out.writeBytes("The Quangle Wangle sat\n");
        out.close();
        System.out.println("Wrote file: " + file);

        // READ + SEEK: open() gives a seekable stream
        FSDataInputStream in = fs.open(file);
        byte[] buffer = new byte[32];
        in.read(buffer);
        System.out.println("From start : " + new String(buffer).trim());
        in.seek(33);                     // jump to absolute byte 33
        byte[] buf2 = new byte[32];
        in.read(buf2);
        System.out.println("After seek : " + new String(buf2).trim());
        in.close();

        // METADATA: getFileStatus
        FileStatus st = fs.getFileStatus(file);
        System.out.println("Length     : " + st.getLen() + " bytes");
        System.out.println("Replication: " + st.getReplication());

        // LIST: listStatus on a directory
        System.out.println("--- listStatus /user/student ---");
        for (FileStatus s : fs.listStatus(new Path("/user/student"))) {
            System.out.println("  " + s.getPath().getName());
        }

        // GLOB: wildcard matching
        System.out.println("--- globStatus *.txt ---");
        for (FileStatus s : fs.globStatus(new Path("/user/student/*.txt"))) {
            System.out.println("  " + s.getPath().getName());
        }
        fs.close();
    }
}
PHASE 4

Compile, package, and run

11Go to the file's folder and verify Java

This prevents both common javac failures: compiling from the wrong directory and running without a compiler in PATH.

containerhadoop@namenode
cd /opt/hadoop
ls -l HdfsDemo.java     # confirm the file is here
java -version
javac -version
hadoop classpath
12Clean build the JAR

rm -rf classes clears any leftover .class files from the first program — that's what stops the old WordCount classes from sneaking into this jar. $(hadoop classpath) supplies the Hadoop libraries the code imports.

containerhadoop@namenode
rm -rf classes hdfsdemo.jar
export HADOOP_CLASSPATH=$(hadoop classpath)
mkdir classes
javac -classpath $HADOOP_CLASSPATH -d classes HdfsDemo.java
ls -l classes/          # MUST show HdfsDemo.class
jar -cvf hdfsdemo.jar -C classes .
jar -tf hdfsdemo.jar    # MUST show HdfsDemo.class, not WordCount
⚠
Check both listings before running If ls classes/ or jar -tf shows WordCount.class (or nothing), the compile didn't take — fix that before the next step, or you'll get ClassNotFoundException: HdfsDemo again.
13Run the program
containerhadoop@namenode
hadoop jar hdfsdemo.jar HdfsDemo
Expected output 
Wrote file: /user/student/quangle.txt
From start : On the top of the Crumpetty Tree
After seek : The Quangle Wangle sat
Length     : 56 bytes
Replication: 1
--- listStatus /user/student ---
  quangle.txt
--- globStatus *.txt ---
  quangle.txt
14Confirm the file really lives on HDFS

The “After seek” line printed the second line of the file — seek(33) jumped straight to byte 33 in one opened stream. That is HDFS's seekable random-access read, the whole point of the lab.

containerhadoop@namenode
hdfs dfs -cat /user/student/quangle.txt

SUMMARY

Purpose and key points

Experiment purpose

To run a single-node HDFS cluster with Docker and use Java's Hadoop FileSystem API to create, read, seek, inspect, list, and pattern-match files stored in HDFS.

Key points
  • The NameNode stores HDFS metadata; the DataNode stores file blocks.
  • fs.create() writes a file and fs.open() reads it.
  • seek(33) demonstrates random access within an HDFS input stream.
  • getFileStatus() reads metadata such as length and replication.
  • listStatus() lists a directory and globStatus() matches a pattern such as *.txt.
  • Replication is set to 1 because this experiment uses one DataNode.
